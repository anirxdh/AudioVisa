<task type="auto">
  <name>Task 2: Define Scene type contract and create validation script</name>
  <files>types/scene.ts, scripts/validate-scenes.ts, data/scenes.json</files>
  <action>
1. Create `types/scene.ts` with the canonical Scene interface. This is the cross-phase contract:
   ```typescript
   export interface Scene {
     id: string;                    // kebab-case slug e.g. "tokyo-fish-market-1990s"
     location: string;              // Specific place: "Tsukiji Fish Market, Tokyo"
     country: string;               // "Japan"
     continent: string;             // "Asia" | "Europe" | "North America" | "South America" | "Africa" | "Oceania"
     era: string;                   // Decade: "1990s"
     difficulty: "easy" | "medium" | "hard";
     description: string;           // 2-3 sentences of atmospheric prose
     sounds: string[];              // 4-6 specific sounds as plain text
     sfx_prompts: string[];         // 2-3 detailed ElevenLabs SFX prompts (min 30 chars each)
     music_prompt: string;          // 1 ElevenLabs Music API prompt
     category: SceneCategory;       // For filtering/generation tracking
   }

   export type SceneCategory =
     | "markets"
     | "historical"
     | "city_streets"
     | "nature"
     | "industrial"
     | "festivals"
     | "transport";
   ```

2. Create `data/scenes.json` with an empty structure: `{ "scenes": [] }`. This is the seed file that Plan 02 will populate.

3. Create `scripts/validate-scenes.ts` — a comprehensive validation script that checks:
   - Total scene count (report count, warn if < 200)
   - Hero scene count: scenes where the first 30 entries are expected to be hero (hand-curated). Check if at least 30 scenes exist.
   - All required fields present on every scene (id, location, country, continent, era, difficulty, description, sounds, sfx_prompts, music_prompt, category)
   - `sounds` array has 4-6 items per scene
   - `sfx_prompts` array has 2-3 items per scene
   - Each sfx_prompt is at least 30 characters long
   - `difficulty` is one of "easy" | "medium" | "hard"
   - `category` is one of the 7 valid categories
   - `id` matches kebab-case regex: `/^[a-z0-9-]+$/`
   - No duplicate IDs
   - Difficulty distribution report: count and percentage of easy/medium/hard (warn if < 30 easy or < 20 hard)
   - Category distribution report: count per category (warn if any category has 0 scenes)
   - All 7 categories represented

   The script should:
   - Read `data/scenes.json`
   - Run all checks
   - Print a summary table
   - Exit 0 if all checks pass (with warnings printed but not failing)
   - Exit 1 if any hard failures (missing required fields, invalid IDs, duplicate IDs, invalid difficulty/category values)
   - Support a `--hero-only` flag that only validates the first 30 scenes

   Import the Scene type from `types/scene.ts` for type checking. Use fs and path (Node built-ins). Do NOT use a test framework — this is a standalone validation script run via `npx tsx`.
  </action>
